# Putting it on the web for a non-technical USER

Read this when the USER wants the work (a list, a small app) reachable on the web or from their phone. The base path: **a Cloudflare Worker + D1 (or KV) on the `*.workers.dev` address, protected by Cloudflare Access.** No domain is needed, and the USER runs no commands; you run them.

Banned: a tunnel or VPN from the USER's machine (trycloudflare, ngrok, Tailscale Funnel/Serve), exposing that machine to the internet, your own password/login page/basic auth, a secret or long URL as protection, `wrangler login` on a headless machine, the token in the chat, in `wrangler.toml` or in git.

## Steps (one or two screens at a time, real menu names)

Going live is the USER's call: deploy only when they asked for it or explicitly said yes; until then build and try it locally. Deploy and check with `.mentat/bin/mentat_web.py` (the installer fetches it). Every done report says whether it is live (and at which address) or only local.

1. **Account:** dash.cloudflare.com → Sign up → confirm the e-mail. If they have an account, they just log in.
2. **Token** (a tool): download the tools once: `curl -fsSL --create-dirs -o '.mentat/bin/web/#1' 'https://raw.githubusercontent.com/lipi4242/mentat/v0.5.0/reference/web/{cf_api.py,mentat_cf_access.py,mentat_cf_token.py,mentat_cf_need.py}'`, then run `python3 .mentat/bin/web/mentat_cf_token.py next` and pass its ONE step on (one or two steps per message), wait for "done", run it again until it says ready. It follows the template (My Profile → API Tokens → the **Edit Cloudflare Workers** template with Workers Scripts · Edit and Account Settings · Read; an existing row is switched Read → Edit, add a row only if there is none; D1 and Access: Apps and Policies at Edit) and checks after every step; `--check` verifies the token and every permission.
3. **Where it goes:** the tool creates the project's `.env` (mode 0600, listed in `.gitignore`); the USER pastes the token into a hidden local form (`mentat_serve.py --secret`, the step prints it). Pasted into the chat anyway: `mentat_secret.py put CLOUDFLARE_API_TOKEN` (stdin) at once, never write it back.
4. **Account id:** the tool records `CLOUDFLARE_ACCOUNT_ID` in `.env` when it says ready.
5. **Storage and deploy:** every step through `mentat_web.py deploy --approved "<their yes>" [--url <address>] -- <command>`: `npx wrangler d1 create <name>` → the binding into `wrangler.toml` (the id is not a secret); schema from `migrations/`: `npx wrangler d1 migrations apply <name> --remote`; then `npx wrangler deploy`. The address is `https://<worker>.<account>.workers.dev`.
6. **On error 10000** (Authentication error): the token lacks a permission; the failing command tells you which (`d1 …` → D1, `kv …` → Workers KV Storage, `deploy` → Workers Scripts). Say exactly: My Profile → API Tokens → … on the token's row → Edit → set the missing row to **Edit** → Continue to summary → Update token. The token value stays the same. Then rerun the same operation. Do not route around it with other storage or a local run.
7. **Protection** (a tool, not buttons): `python3 .mentat/bin/web/mentat_cf_access.py ensure --worker <worker> --email <the USER's e-mail> [--email …]`. It is idempotent; `check --worker <worker>` says whether Access is on; exit 2 names the missing token permission (add it as in step 6). Access does the protecting; the worker adds no check of its own. To know who is signed in, use `ctx.access`; full JWT checking only with `POLICY_AUD` and `TEAM_DOMAIN` set, else every request gets 403. Before calling it live: a signed-in request (browser, or the `CF_Authorization` cookie) returns 200 and the data; an unsigned one goes to the sign-in page: `mentat_web.py check <address> --cookie-file <file>` prints OK. If they say "no password needed", first tell them that without it anyone sees the data, and ask.
8. **Data:** upload the whole cleaned, read-back list (not the raw file); anything doubtful or closed is a status field, not a filter. Before uploading, agree with the USER: how many items go up, what was left out or merged, and why. An SQL file → `npx wrangler d1 execute <name> --remote --file …`.
9. **Try it:** after the first deploy, as the USER, signed-in (not the raw URL): `mentat_web.py check <address> --cookie-file <file> --contains <item count>`; only then call it done.
10. **Later changes:** back up first (`npx wrangler d1 export <name> --remote --output …`), then a migration (`ALTER TABLE`, a new file in `migrations/`), then deploy. Never create a new database or reload old data over the live one.

Mentat Admin (`admin/`, Mentat's todo + backlog) fits when the USER wants to manage their todos, cases or backlog there: it has its own e-mail sign-in, which needs a mail domain. For a simple list, use this path.
